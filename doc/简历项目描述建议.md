## 完整版

**高校任务管理系统（多租户 SaaS + AI 智能助手）**　　2026.xx – 至今

技术栈：Spring Boot 2.5 / MyBatis / MySQL / uni-app(Vue2) / GLM-4.5-Air(Function Calling) / SSE / nginx / HTTPS

面向高校二级学院的任务、会议、重点工作管理平台，支持多租户数据隔离与角色权限；核心负责 AI 智能助手的架构设计与落地，实现自然语言查询、语音输入与流式对话。

- **AI 对话引擎**：基于 GLM-4.5-Air Function Calling + 多轮工具调用实现自然语言查库，SSE 流式输出（实测首包 2.4s）；设计"常驻参考层"——租户字典/科室/人员以中文值形式缓存注入系统提示词（10 分钟 TTL），模型只传中文值、后端确定性解析为 ID，解决小模型抄写长 UUID 出错导致的查询失败；
- **防幻觉三层防线**：① 意图门控与机制化菜单——模糊提问、筛选、翻页等确定性交互由后端直接返回，零模型调用（约占日常提问 20%）；② 零工具调用检测 + 纠错重试——模型跳过工具复述上文列表时，机制性注入纠错指令重试拉回；③ 编造识别兜底——列表式回答无可追溯查询来源时拦截替换，宁可拒答不放假数据；
- **上下文与多轮体验**：对省略式追问（"那会议呢"）、是非确认（"是"）、独立新查询做意图分类与差异化注入，解决"查最近任务被上一轮人名条件污染"、"答'是'被反问丢上下文"等多轮对话典型问题；任务条目与选项随消息落库，历史会话恢复后链接可点、按钮可用；
- **语音输入**：仿微信输入栏（按住说话、左滑取消、右滑转文字），getUserMedia + recorder-core 采集 16kHz WAV 对接 GLM-ASR；主导 HTTPS 落地（自签证书含 IP SAN + nginx 443），解决浏览器安全上下文对麦克风的限制；
- **部署与成本**：nginx 反代 /api 同源规避混合内容，SSE 场景关闭 proxy_buffering 实现打字机效果；完成 API 成本测算（单次问答 <1 分钱，100 人 × 50 次/天规模年费约 1.6 万），沉淀缓存命中率、机制化免模型轮等降本手段。

## 面试官大概率追问的问题（提前准备）

1. **为什么用 Function Calling 而不是 text2SQL？**
   → 权限收口：工具内部走带租户/角色过滤的 Service 层，模型永远碰不到 SQL；参数可校验（人名→getUsers 容错解析），text2SQL 有注入和越权风险。
2. **防幻觉具体怎么做？误判了怎么办？**
   → 看来源不看内容：零工具调用却输出列表式数据即拦截；误杀代价是多查一次库（用户无感），漏放代价是用户基于假数据决策——成本不对称，偏向误杀。
3. **为什么让模型传中文值而不是 ID？**
   → 实测小模型抄 36 位 UUID 会抄错（把科室 ID 当状态 ID 传）；中文值短、可读、错了能容错匹配，ID 解析放后端做确定性兜底。
4. **上下文污染怎么发现的？**
   → 从对话落库记录还原用户真实上下文复现（例："查下最近任务"被上一轮"李慧秋"污染），比盲猜问法高效——体现排查方法论。
5. **SSE 和 WebSocket 为什么选前者？**
   → 单向流式场景，SSE 基于 HTTP 免改造、nginx 配合 `proxy_buffering off` 即可，无需维护长连接状态。
6. **多租户怎么隔离的？**
   → 每表带 tid，登录态解析租户，Service 层统一注入查询范围（角色分级：院领导/科室/个人看到不同数据集）。
7. **成本怎么控制的？**
   → 系统提示词+工具定义是固定前缀，prompt 缓存命中 ~90%；20% 交互走机制菜单零模型调用；历史截断 10 条 + 单次返回上限 20 条控制 token。
