# AI 助手代码修改思路

> 适用版本：2026-08
> 涉及范围：`backend/springboot`（后端）、`task-miniprogram`（前端 H5）

---

## 一、整体架构

AI 助手采用 **大模型 Function Calling（函数调用）+ 复用现有权限体系** 的架构，核心原则：

```
用户提问 → GLM 大模型 → 选择工具(function) → 后端执行工具 → 结果回传大模型 → 生成最终回答
                                    ↓
                      复用现有 Service / Mapper / 权限校验（不直接查库）
```

1. **AI 不直接接触数据库**：大模型只能"调用工具"，工具在后端执行时复用现有 Service 方法（如 `planService.getPlanPage`），没有为 AI 单独写业务 SQL。
2. **身份由 Token 决定，不由前端传**：请求经过 `JwtInterceptor`，`TokenUtils.getCurrentUser()` 在同一请求线程上取到当前用户。AI 查询永远是"以当前登录用户的身份"在查。
3. **权限与 Web 端点完全一致**：把 `PlanController.searchPlanByConditionPage` 里的数据范围控制逻辑抽取为 `AuthCheckUtils.applyPlanQueryScope(plan)`，Web 接口和 AI 工具共用同一份代码。用户能查到的任务 = 他在网页上能看到的任务。

## 二、后端核心改动

### 2.1 数据范围控制抽取（AuthCheckUtils）

- 新增 `AuthCheckUtils.applyPlanQueryScope(Plan plan)`，原逻辑从 `PlanController` 抽出。
- 依据用户权限（`plan:operate:get:college / get:office / get:ordinary`）与任务是否公开（isopen），控制可查询范围，越权抛 `AuthorityException`。
- `PlanController` 与 AI 工具执行器都调用它，保证一处修改两边生效。

### 2.2 AI 对话服务（AiChatService）

文件：`service/AiChatService.java`

- `chat(message, history, sessionId)`：同步对话，返回 `{sessionId, answer}`。
- `chatStream(message, history, sessionId, sink)`：流式对话，把 Function Calling 循环里每一步实时推给前端（详见第六节）。
- 工具调用循环最多 `MAX_TOOL_ROUNDS = 5` 轮，防止死循环；每轮工具结果以 `role=tool` 消息回传大模型。

**注册的 4 个工具：**

| 工具 | 作用 | 安全控制 |
|---|---|---|
| `getTasks` | 按条件查任务（关键词/状态/类型/重要程度/性质/负责人/科室/时间/我的/分页） | 强制 `tid=当前租户`、走 `applyPlanQueryScope`、单页最多 20 条、负责人ID批量转姓名、detail 截断 |
| `getDictOptions` | 返回状态/类型/重要程度/性质的字典 id-name 对照 | 只查本租户字典 |
| `getUsers` | 按姓名模糊查用户，把"张三"解析成 userId | 强制 `tid`、只返回 id/name/department/role（**SQL 返回 password，代码手动挑选字段脱敏**）、最多 10 条；查不到时返回相近姓名候选（见错误提示文档） |
| `getDepartments` | 返回本租户科室 id-name 对照 | 只查本租户 |

**多跳解析设计**：用户说"张三本周的任务"，大模型需要先 `getUsers("张三")` 拿到用户 id，再把 id 作为 `headId` 传给 `getTasks`；状态"进行中"要先 `getDictOptions` 拿字典 id。这些解析规则写进系统提示词（`buildSystemPrompt`），共 7 条工具规则 + 5 条输入纠错引导规则。

**硬规则（写进系统提示词）**：
- 涉及真实数据必须调工具，严禁编造；
- 第一人称查询（"我的任务"）必须传 `mine: true`；
- 查询无结果如实告知，error 如实转述，不重试超过两次。

### 2.3 会话持久化（历史对话）

- 表：`ai_chat_session`（会话，软删 isdelete）、`ai_chat_message`（消息）。
- **关键设计**：`ai_chat_message` 增加 `seq BIGINT AUTO_INCREMENT` 列。同一轮问答的两条消息（问+答）共用 `now()` 时间戳，UUID 主键排序是随机的，会导致"答在问前"；用 `seq` 排序保证绝对顺序。建表脚本：`sql/ai_chat_init.sql`。
- `resolveSession`：sessionId 属于当前用户则复用，否则新建（标题取首条消息前 20 字）。
- `loadMessages` / `deleteSession` 都先校验 `getByIdAndUid`，只能操作自己的会话；删除 = 会话软删 + 消息物理删（不留敏感内容）。

### 2.4 语音识别（AsrService）

- 方案：**前端 H5 录音 + 后端智谱 GLM-ASR**（前端是 HBuilder 打包的 H5 网页，不是微信小程序，因此不能用微信同声传译插件）。2026-08-30 由百度 ASR 迁移至智谱，语音与对话共用同一个 `glm.api-key`，少维护一套密钥。
- `AsrService.recognizeWav(byte[])`：`POST {glm.base-url}/audio/transcriptions`，multipart 上传（model=glm-asr-2512 + file），Bearer 认证；音频要求 wav/mp3、≤30秒、≤25MB（前端 recTimer 已按 30 秒自动截断）。glm-asr 为**付费模型**，账户需有余额或资源包，否则返回错误码 1113（余额不足）。
- 接口 `POST /ai/asr`（multipart 上传）。

### 2.5 流式思考过程（SSE）

文件：`AiChatController.chatStream` + `AiChatService.chatStream/doChat/describeTool`

- 新增 `POST /ai/chat/stream`，响应 `text/event-stream`，事件协议（每条 `data: {JSON}`）：
  - `{"type":"step","content":"查阅任务字典…"}` —— 思考步骤
  - `{"type":"done","sessionId":"…","answer":"…"}` —— 最终结果
  - `{"type":"error","content":"…"}` —— 异常
- `doChat` 把原 `chat` 逻辑抽出，每个工具调用执行前用 `describeTool` 把"工具名+参数"翻译成自然语言步骤（如 getUsers → "正在把「张三」解析为系统用户…"）。
- **有意选择在请求线程同步执行**：`JwtInterceptor` 填充的用户上下文在 ThreadLocal，异步线程取不到身份。同步执行 simplest & 零风险。
- 用 `HttpServletResponse` 手写 SSE 而非 `SseEmitter`，避免异步容器/超时配置问题；lambda 引用变量需 effectively final（踩坑一次）。
- 老接口 `/ai/chat` 保留，供独立测试页 `ai-test.html` 使用。

### 2.6 输入纠错引导（用户输错也能被引导）

三层机制（详见《错误提示依据.md》）：

1. **工具层**：`getUsers` 精确/模糊匹配为空时，取全租户用户做**姓名字符重合度**评分，返回相似度最高的 5 个候选 + `exactMatch:false` + 引导性 note；
2. **工具层**：`getTasks` 查到 0 条时返回归因提示（时间过窄/姓名或科室不对/状态理解偏差），提示大模型主动放宽条件重查；
3. **提示词层**：新增"输入纠错与引导策略"规则块（a~e 条）：列相似姓名让用户确认、字典对不上列实际选项、科室对不上列相近科室、结果为 0 归因并放宽重查、查询外需求引导去页面操作。

## 三、前端核心改动（task-miniprogram）

### 3.1 AI 聊天页 `src/pages/ai/ai-chat.vue`

- **消息结构**：`{role, content, thinking[], thinkingDone, thinkOpen}`。AI 消息带思考步骤数组，乐观推入第一步"正在理解你的问题…"，体验即时。
- **流式接收**：axios 不支持流式，`send()` 改用原生 `fetch + ReadableStream` 读取 SSE，手动带 `token` header（与 request.js 一致，取 `uni.getStorageSync('token')`）；按 `\n\n` 分帧、`data:` 行解析 JSON。
- **思考过程 UI**：浅蓝渐变卡片，标题栏有呼吸灯圆点（思考中蓝色脉冲/完成绿色），步骤逐条淡入动画；`done` 后自动折叠、可点击标题回看；历史恢复的老消息无 thinking 字段自然不渲染区块。
- **打字机效果**：`done` 事件后 `typeAnswer` 每 30ms 追加 3 字符；定时器记录在 `typeTimers`，`onUnload` 统一清理。
- **滚动**：scroll-view 用"递增大值 scroll-top"方案（`messages.length * 99999 + 99999`），因为 scroll-into-view 相同值不重复触发。
- **语音**：`recorder-core` 录 wav（16kHz/16bit，60 秒自动提交，<500ms 拒绝），FormData 上传 `aiApi.asr`，识别文本自动发送。
- **历史会话**：底部抽屉（分页拉会话列表/切换会话/确认删除）；`onLoad` 默认恢复最近一次对话（带 `this.sessionId` 竞态保护）。
- **navbar**：uview `u-navbar` 需 `:placeholder="true"` 占位，否则消息被固定导航遮挡；`.chat-list` 需 `min-height:0` 才能在 flex 容器内滚动。

### 3.2 悬浮入口"爱宝" `src/components/aibao-float/aibao-float.vue`

- easycom 规则 `^aibao-(.*)` 自动注册，四个主页（index/dept/admin/user）引入 `<aibao-float />`。
- 支持 `bottom` 属性（默认 140rpx）：index 页远端合并后新增了悬浮"+"按钮(180rpx)和返回顶部(280rpx)，传入 `bottom="380rpx"` 上移避让。
- 图片 `/static/aibao.png` 加载失败自动降级为占位样式（🤖+爱宝）。

### 3.3 路由与接口

- `pages.json`：注册 `pages/ai/ai-chat`（AI助手）。
- `src/api/index.js`：`aiApi = { chat, asr, sessions, messages, deleteSession }`，chat 超时 60s。

## 四、配置与密钥（application.yml）

```yaml
glm:
  base-url: https://open.bigmodel.cn/api/paas/v4
  api-key: ${GLM_API_KEY:xxx}   # 默认值已写入 application.yml，环境变量可覆盖
  model: glm-4-flash
  asr-model: glm-asr-2512       # 语音转文本(付费)
```

后端启动（开发环境）：

```bash
cd backend/springboot
mvn spring-boot:run -DskipTests
```

密钥已按默认值形式写入 `application.yml`（私有仓库，确认可入库）；若设置了 `GLM_API_KEY` 环境变量，仍优先使用环境变量。写入原因：环境变量随启动进程丢失，换方式重启后端会导致 AI 功能静默失效。语音识别已于 2026-08-30 迁移至智谱 GLM-ASR，不再需要百度密钥。

原前后端是两个独立 git 仓库（gitee），后改为**根目录单一仓库**上传 GitCode（`ai_manage`）：

- 根 `.gitignore` 合并两端规则：`node_modules/`、`target/`、`logs/`、`.idea/`、`*.iml`、`.git-gitee-backup/` 等。
- backend 的 `.gitignore` 修正：原 `/logs/` 未覆盖 `springboot/logs/`，已补 `/springboot/logs/`。
