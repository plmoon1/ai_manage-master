# AI 助手错误提示依据

> 说明：每条提示都对应明确的触发条件与代码依据，按用户感知路径分类。
> 设计总原则：① 不向用户暴露内部异常细节（安全）；② 错误提示带引导（告诉用户下一步怎么做）；③ 数据真实，查不到就如实说。

---

## 一、对话请求类（后端 → 用户）

### 1.1 消息为空
- **提示**：`消息不能为空`
- **触发**：`POST /ai/chat` / `/ai/chat/stream` 收到的 `message` trim 后为空
- **依据**：`AiChatController` 入参校验

### 1.2 消息超长
- **提示**：无提示，静默截断前 2000 字
- **触发**：message 长度 > 2000
- **依据**：`AiChatController`，防止超长输入拖垮大模型上下文与费用

### 1.3 GLM 服务异常
- **提示**：`AI 服务异常，请稍后重试`
- **触发**：GLM 接口返回 error / 响应异常 / 网络失败
- **依据**：`AiChatService.chatStream` 统一 catch；同步接口 `/ai/chat` 由 Controller catch 返回 `AI 服务异常：...`
- **为什么不显示原始错误**：异常信息可能包含接口地址、密钥片段等内部实现，回传前端有泄露风险

### 1.4 未配置 API Key
- **提示**：后端日志 `GLM API Key 未配置(glm.api-key)`，接口报 500
- **触发**：环境变量 `GLM_API_KEY` 为空时启动后调用对话接口
- **依据**：`AiChatService.doChat` 启动检查

### 1.5 查询超时/轮次耗尽
- **提示**：`这个问题需要查询的数据较多，处理超时。请缩小范围后重试（例如指定时间或状态）。`
- **触发**：Function Calling 循环达到 5 轮上限仍没有最终回答（`MAX_TOOL_ROUNDS = 5`）
- **依据**：`AiChatService.doChat` 循环兜底文案，防死循环

### 1.6 工具执行失败
- **提示**（回传给大模型）：`查询失败，请提示用户稍后重试或缩小查询范围`
- **触发**：executeTool 抛异常（数据库异常等）
- **依据**：`doChat` 工具循环 catch；不把 Java 堆栈回传给模型，避免模型复述泄露内部信息

### 1.7 鉴权失败
- **提示**：`{"code":"401","msg":"无效的token"}`
- **触发**：请求未带 token / token 过期 / token 伪造
- **依据**：`JwtInterceptor` 统一拦截 `/ai/**`；前端收到后由 request 拦截器跳转登录页（fetch 流式路径则显示"请求失败"）

## 二、查询结果引导类（"查不到"时的依据）

### 2.1 负责人姓名不匹配
- **提示**：AI 会列出系统里实际存在的相近姓名请用户确认，例如：
  > 没有找到「张三丰」，系统里有这些相近的姓名：张三（XX科）、张三三（YY科），请问你找的是哪一位？
- **触发依据**：`getUsers` 先按 `name like '%keyword%'` 查询（本租户），为空时取全租户用户做**字符重合度评分**（keyword 与姓名的公共字符数），取分>0 的前 5 名，返回 `exactMatch:false` + 引导 note
- **代码**：`AiChatService.toolGetUsers / topSimilarUsers`
- **约束**：大模型被规则要求"确认后才能继续查询，不要用未匹配的姓名继续查"

### 2.2 多个同名用户
- **提示**：`匹配到多个用户，请让用户确认是哪一位（可结合科室区分）`
- **触发**：getUsers 姓名模糊匹配到 >1 人
- **依据**：`toolGetUsers` note 字段，防止查错人的任务

### 2.3 状态/类型/重要程度说法不规范
- **提示**：AI 列出系统实际可选项让用户选，例如：
  > 系统里没有"搁置"这个状态，现有状态为：进行中、未开始、已完成、已撤销，请问您指哪种？
- **触发依据**：用户用词在 `getDictOptions` 返回的字典里找不到对应项时，系统提示词规则 b 禁止硬套
- **为什么不让模型猜**：字典 id 是任务表实际存储值，猜错会静默查错数据

### 2.4 科室名不匹配
- **提示**：列出 `getDepartments` 里相近的实际科室名让用户确认
- **触发依据**：用户说法与科室表 name 对不上，系统提示词规则 c

### 2.5 条件有效但结果为 0
- **提示**：AI 分析原因并建议放宽，必要时自动放宽重查，例如：
  > 张三最近三个月没有已完成任务，可能时间范围偏窄，需要我查他今年全部任务吗？
- **触发依据**：`getTasks` 返回 `total=0` 时附带归因 note（常见原因：时间范围过窄、负责人姓名有误、状态理解偏差），系统提示词规则 d 要求"指出最可能条件 + 放宽建议 + 可主动重查一次"

### 2.6 数据条数过多
- **提示**：AI 提示可缩小范围或翻页，例如：
  > 共 87 条，先列出最新的 20 条，需要继续翻页吗？
- **触发依据**：`toolGetTasks` 单页上限 `MAX_PAGE_SIZE=20`，超出时返回 note 说明总数；防止把大结果集塞进上下文（拖慢响应、增加费用）

### 2.7 超出能力范围的需求
- **提示**：`当前仅支持任务查询，创建/修改任务请在系统对应页面操作`（大意）
- **触发**：用户要求创建/修改/删除任务、查会议、查重点工作等
- **依据**：系统提示词规则 e——AI 工具集只有 4 个查询工具，诚实告知比编造安全

## 三、会话管理类

### 3.1 会话不存在或无权访问
- **提示**：`会话不存在或无权访问`
- **触发**：`GET /ai/messages?sid=` 传入的会话不属于当前用户（含伪造 sid）
- **依据**：`AiChatService.loadMessages` 先 `getByIdAndUid` 校验归属；接口返回 403

### 3.2 删除会话
- **提示**：前端二次确认弹窗「确定删除「xx」吗？删除后不可恢复」
- **依据**：前端 `removeSession` 用 `uni.showModal` 确认；后端软删会话 + 物理删消息（隐私不留痕）

## 四、语音识别类

### 4.1 麦克风权限被拒
- **提示**：`请允许网页使用麦克风`
- **触发**：浏览器 `getUserMedia` 拒绝授权（recorder-core `isUserNotAllow`）
- **依据**：`ai-chat.vue onVoiceStart` 失败回调区分"用户拒绝"与"设备不可用"两类提示

### 4.2 录音不可用
- **提示**：`录音不可用：<原因>`
- **触发**：无麦克风设备、浏览器不支持等
- **依据**：recorder-core open 失败回调

### 4.3 说话时间太短
- **提示**：`说话时间太短`
- **触发**：录音时长 < 500ms
- **依据**：`finishVoice` 中 `duration < 500` 判断——太短的音频送 ASR 必然无意义结果，前置拦截省一次调用

### 4.4 录音超长
- **提示**：无提示，30 秒自动停止并提交
- **依据**：智谱 GLM-ASR 单次识别上限 30 秒，前端 `recTimer` 定时 30s 自动 `finishVoice`，与后端限制对齐

### 4.5 未识别到内容
- **提示**：`未识别到语音内容`
- **触发**：ASR 成功但返回空文本（噪音/无语音）
- **依据**：`uploadVoice` 判断识别结果为空

### 4.6 语音识别失败
- **提示**：`语音识别失败：<原因>`（request 拦截器统一 toast）
- **触发依据**：`AsrService` 各种失败——音频超过 8MB（`MAX_AUDIO_BYTES`）、GLM-ASR 接口错误（如 1113 余额不足或无可用资源包）等

## 五、前端交互类

### 5.1 流式请求失败
- **提示**：`请求失败，请稍后重试`（显示在 AI 气泡内）
- **触发**：fetch 失败、HTTP 非 200、响应无 body、流中断
- **依据**：`ai-chat.vue send()` catch 分支；思考区块同时折叠并标记完成

### 5.2 服务端 error 事件
- **提示**：后端推送的 `{"type":"error","content":"..."}` 内容直接显示
- **触发**：对话处理中异常（见第一节）
- **依据**：SSE 事件协议三类型 step/done/error，前端 `handleAiEvent` 分发

### 5.3 空回复
- **提示**：`(空回复)`
- **触发**：done 事件 answer 为空
- **依据**：`handleAiEvent` 兜底，避免气泡空白

### 5.4 加载中防重
- **提示**：无（输入框置灰、发送按钮禁用）
- **触发**：上一问未完成时
- **依据**：`loading` 状态绑定 `:disabled`，防止并发请求导致会话错乱
